## 最新：播放循环断供修复与网络现场

- 用户要求串口排查后，在正确仓库配置固件上重新采集基线：station 3，4 个窗口共 120.550 秒，送出 PCM 110.181 秒（91.4%）；无读取超时或崩溃，仍有数百毫秒读取等待。
- 根因之一：原循环把预缓冲完整帧一次解码用完，再进行可阻塞 1.5 秒的 HTTP 读取。I2S 队列只能覆盖很短时间，网络短暂停顿因此直接中断喂音。生产函数主机测试复现 200 ms 无数据时旧循环断供 146.950 ms；逐帧调度修复后该场景断供为 0。
- 保留原 4096 字节输入、4608 字节 PCM、6144 字节任务栈及现行仓库 SDK 配置，不新增任务或 DMA。每轮输出一帧、补充至多 256 字节，有完整帧可播时读取等待 2 ms；短轮询无数据继续播放储备，不误触发缓冲。
- 另一个恢复缺口是缓冲耗尽后，长读即使成功也没有重新储备。已改为耗尽立即进入缓冲并重新积累 3584 字节；主机长抖动用例从只收 256 字节便续播，修正为补足 3584 字节再续播。读错误和 EOF 先输出已有完整尾帧再重连，错误状态不伪装成成功。
- 中间修复版 `fcefdea1549b6814f2ea5973c8263d4fe7ebb0549d751b84ce1af9c6212a2bf7` 采样 151.248 秒 / PCM 147.248 秒，用户明确反馈“明显改善，暂未听到卡顿”。后续补入上述耗尽恢复和接收现场诊断；不把这次听感反馈扩大为所有台站或最终版本长期验收。
- 最终应用 `build_linux_repo/FoloToy-AI-Passport.bin`：1,999,696 字节，应用分区余 97,456 字节，静态 DRAM 余 112,422 字节；SHA-256 `83ca3f58a6bdb842993c02839ad78db3e02290e1f424b1ab1abad45aa72dd61d`。ESP-IDF 5.5.4 build/size 通过，SDK 声明项逐一匹配仓库；47 项主机测试通过、0 失败，10 条现有 Pillow 弃用警告。
